## ARM (aarch64) Linux

TabbyAPI runs on 64-bit ARM Linux machines with an NVIDIA GPU, such as Grace Hopper and Grace
Blackwell systems, DGX Spark, and ARM servers with discrete NVIDIA cards. The `cu12` and `cu13`
extras install PyTorch's aarch64 CUDA builds, the same versions as on x86_64.

ExLlamaV3 doesn't publish ARM wheels. On ARM the extras install its universal wheel instead, which
compiles ExLlamaV3's CUDA extension on the machine the first time it is imported. TabbyAPI says so
in its log when that happens.

### Requirements

- Linux on aarch64 with glibc 2.31 or newer, e.g. Ubuntu 22.04 or newer
- Python 3.12 to 3.14 for `cu13`, 3.10 to 3.13 for `cu12`
- An NVIDIA driver that supports the CUDA version of the chosen extra
- A CUDA toolkit with `nvcc`, of the same major version as the extra: CUDA 13.x for `cu13`,
  12.x for `cu12`. torch refuses to build with a different major version. Check with
  `nvcc --version`; if `nvcc` isn't on `PATH`, set `CUDA_HOME` to the toolkit's root
  (e.g. `/usr/local/cuda`)
- A C++ compiler and the Python headers, e.g. `sudo apt install build-essential python3.12-dev`
  (uv-managed Pythons include the headers)

Jetson Orin and older Jetson boards need NVIDIA's JetPack builds of PyTorch, which the extras
don't install.

### Installing

1. With the start script: run `start.sh`. On ARM it picks `cu13`, or `cu12` when the installed
   `nvcc` is CUDA 12. Choose explicitly with `--gpu-lib cu13` or `--gpu-lib cu12`.
2. Manually, in a virtual environment:

   ```sh
   pip install -U .[cu13]
   ```

### First start

The first start compiles ExLlamaV3's extension, which can take a while. The result is cached in
`~/.cache/torch_extensions` (or `TORCH_EXTENSIONS_DIR`) and reused by later starts until torch,
ExLlamaV3 or the CUDA version changes.

- The build runs one compiler job per CPU core. On a machine with little memory per core, limit
  it with `MAX_JOBS`, e.g. `MAX_JOBS=4 ./start.sh`.
- The extension is built for the GPUs it sees. To build it without a visible GPU, or for other
  GPUs, set `TORCH_CUDA_ARCH_LIST`, e.g. `TORCH_CUDA_ARCH_LIST="9.0;12.0+PTX"`.
- To build it ahead of time, for instance right after installing, run
  `python -c "import exllamav3.ext"` in the virtual environment.

### Limitations

- The `native` tensor parallel backend reduces on the CPU with x86 (AVX) code. On ARM TabbyAPI
  uses the `nccl` backend instead and logs a warning.
- CPU MoE inference (`cpu_moe_offload_layers`, `cpu_moe_split_experts`) is x86-only in ExLlamaV3.
  Loading a model with either option set fails with an error on ARM.
- The ROCm extra and the published Docker images are x86_64 only.
